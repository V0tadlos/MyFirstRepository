# MyFirstRepository
Markdown — облегчённый язык разметки, который используется для простого форматирования отображаемого текста. 
Markdown используется в GitHub в комментариях к задачам и для создания подробного описания или инструкции в репозитории (с помощью файлов с расширением .MD).

Синтаксис Markdown
Markdown позволяет делить текст на абзацы; добавлять списки, ссылки, изображения, цитаты и код; 
выделять текст жирным или курсивом, а также предоставляет другие возможности, о которых можно почитать здесь и здесь.

Познакомимся с основами синтаксиса Markdown:

Символы	Описание
# Заголовок	                                Используется для обозначения заголовка 1-го уровня.
## Заголовок	                              Используется для обозначения заголовка 2-го уровня, и так вплоть до 6-го уровня.
*Текст*	                                    Используется для выделения текста курсивом.
**Текст**	                                  Используется для выделения текста жирным.
* Текст	                                    Используется для обозначения элемента ненумерованного списка.
1. Текст	                                  Используется для обозначения элемента нумерованного списка.
[Название ссылки](Адрес ссылки)	            Используется для добавления ссылки.

### Что нам еще следует изучить
* Ветка (Branch)
* Отправка в удаленный репозиторий (Push)
* Обновление локального репозитория (Pull / Fetch)
* Слияние (Merge)
* Коммит слияния (Merge commit)
  когда в каждой ветке есть свои коммиты
* Дополнение коммита (Amend)
  Пока коммит на вашем локальном репозитории галочка Amend
* Отмена изменений файла (Discard)
  Достаточно нажать на файл ПКМ и выбрать Отменить изменения.
* Добавление .gitignore
  почитать можно здесь https://tyapk.ru/blog/post/gitignore
* Хранилище незавершенных изменений (Stash) Вместо кнопки Зафиксировать все выберем Спрятать все
  в разделе Спрятанные изменения добавится только что сохраненные в Stash изменения
  Для того чтобы вернуть эти изменения, когда они будут нам нужны, на выбор доступны 2 возможности — применить и извлечь.
  При применении изменения останутся в хранилище после применения к текущей ветке, а при извлечении —   будут удалены после успешного применения.
* Cherry-Pick
  Данная функция позволяет скопировать определенный коммит из другой ветки к себе, создав абсолютно идентичный, но новый коммит.
  Нужно перейти в историю другой ветки, выбрать нужный коммит, нажать ПКМ и выбрать Отбор изменений:
* Отмена коммита (Revert)
  Revert создает коммит, отменяющий изменения выбранного коммита.
  На простом примере: был коммит, в котором добавлялся один файл, а в другом изменилось 10 строк.
  Revert создаст коммит, в котором первый файл будет  удален, а во втором 10 строк будут изменены до первоначального состояния.
  В Visual Studio это делается нажатием ПКМ на коммит и выбором пункта Отменить:
